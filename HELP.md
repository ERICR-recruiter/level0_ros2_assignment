## Get started
- You'll need ROS2 Foxy/Galatic/Humble installed, if you haven't already. (Install Humble from [Humble Installation](https://docs.ros.org/en/humble/Installation.html)) (You will need Ubuntu 22.04/Windows 10 for this.)

- **turtlesim**
  - The simulator used for the assignment.
  - Install with:
    ```bash
    sudo apt-get install ros-humble-turtlesim
    ```
    *(Replace `humble` with your ROS 2 distro if needed.)*

- **nav_msgs**
  - Provides the `Odometry` message type for publishing odometry data.

- **geometry_msgs**
  - Required for transform messages and pose data.

- **tf2_ros**
  - For broadcasting and managing coordinate transforms (TFs).

- **tf2_tools** *(optional but recommended)*
  - Useful for debugging and visualizing TF trees.

- **rviz2**
  - Visualization tool for ROS 2, used to view odometry and TF frames.
  - Install with:
    ```bash
    sudo apt-get install ros-humble-rviz2
    ```

## Hints
1. For sections one and two, look into the various message types involved, their structure and what data-types are accepted by them.
2. Make sure the "base_link" TF, in Rviz, follows the same movement and heading as your turtle in the turtlesim simulator.
3. For the turtle autonomy, you can structure your code as follows:
    - `turtle_ctr_node.py`:
        - Includes the motion model for the turtle, used by a function called `generate_path_options`. Here, you can use the `numpy.arrange()` function to generate an array of theta values, which then can be converted into w. Now you have your model input!
        - Another function called `best_path` that simply takes in all the paths generated by the previous function, and calculates the distance to goal_pose if the turtle followed that path.
        - Subscribes to the current pose and publishes the best path to goal, along with the current distance to goal.
    - `turtle_nav_node.py`:
        -  Subscribes to your control node and publishes to /cmd_vel with some constant v and the best heading.
